# 维护手册

本仓库以可独立使用的 Skill 为维护单位，分类、索引与版本记录在仓库层维护。日常变更流程为：定位需求 → 修改必要文件 → 验证 → 更新记录 → PR 审阅 → 合并。具体贡献步骤见 [CONTRIBUTING.md](../CONTRIBUTING.md)。

## 变更范围与索引

新增或移动 Skill 时同步更新 [skills.json](../skills.json)、分类 README、[README.md](../README.md) 索引、内部资源链接和 [CHANGELOG.md](../CHANGELOG.md)。Skill 名是调用接口，尽量保持稳定；改名或移除时说明受影响的调用名称、安装路径及替代方法，不直接让旧文档失效。

源码、参考资料和素材必须各有用途。删除资源前用 `rg` 搜索文件名及路径，检查调用方；删除重复说明时保留单一可靠入口。暂存截图、下载包、缓存、机器专用配置和验证产物留在未跟踪工作目录中。

## 参考来源更新

参考网页或产品发生变化、链接失效，或用户提出与当前指导冲突的实际案例时，重新观察受影响的部分。维护来源记录时注明 URL、观察日期、观察环境和证据的适用范围。无法重新访问时保留旧记录，并明确其观察日期，不写成当前状态。

在设计指导中区分三种内容：

- **来源事实**：来自可核对的原始材料，例如页面声明、实际资源或源码中的值；说明出处。
- **现场观察**：在指定视口和状态下看到或测得的效果；说明环境与测量方式，不推断实现方式。
- **设计建议**：为通用业务、响应式、可用性或性能提出的默认参数；允许用户与项目覆盖。

例如，观察到圆角卡片不能证明原站使用某个框架；建议 18px 圆角不能写成全站实测值。来源设计语言可用于分析，但原站商标、文案、插画和专有字体不自动成为本仓库可分发资源。

## 验证与审阅

每次提交前在仓库根目录运行：

```sh
python scripts/validate_skills.py
npm run check:assets
git diff --check
```

这些检查用于发现结构、资源或格式问题，不保证 Skill 的选择与生成效果。修改脚本时运行受影响脚本；修改入口决策或触发范围时用一个代表性请求检查是否正确适用，以及是否保留用户意图。网站类变更根据内容检查桌面和手机布局、核心交互、键盘焦点与减少动画设置。文案或链接的小改动按影响范围验证即可。

PR 审阅重点是用途和范围、描述与实际能力一致性、来源可靠性、相对资源完整性、可执行检查结果，以及是否引入无关依赖或额外审批要求。记录当前无法验证的限制，不用“完善”“全覆盖”等标签替代证据。

## 版本与发布

使用仓库级语义版本 `MAJOR.MINOR.PATCH`，Git tag 格式为 `v0.1.0`。这是仓库发行版本，不是所有 Skill 的同一成熟度承诺。`CHANGELOG.md` 的 `Unreleased` 持续记录待发布变化，条目写出受影响的 Skill：

- PATCH：纠错、链接修复、保持主要行为的细节改进。
- MINOR：新增 Skill，或向后兼容的能力与资源。
- MAJOR：删除或改名、改变调用方式，或导致既有使用者必须迁移的行为变化。

初始 `0.x` 阶段发生迁移性变化可递增 MINOR，同时仍明确标记并给出迁移说明。不要把纯排版变化称为破坏性变更。

发布前确认工作区没有遗漏、相关检查通过、Changelog 已整理到版本及日期名下，并同步 [VERSION](../VERSION)、[package.json](../package.json) 和 [package-lock.json](../package-lock.json) 的根版本。可用 `npm version 新版本号 --no-git-tag-version` 同时更新两个 npm 文件，再更新 VERSION。维护者选择版本后，创建带说明的 tag 并推送：

```sh
git tag -a v0.1.0 -m "Release v0.1.0"
git push origin v0.1.0
```

示例版本仅供说明，使用尚未发布的新版本号。GitHub Release 可附变更摘要及源码包；发布权限遵循仓库和当前用户授权，不由 Skill 自动扩大。

## 回滚与修复

合并后发现错误时，先确认影响范围并选择修复提交或回滚提交。共享分支用 `git revert <commit>`；合并提交需要先确认主线父提交再使用 `git revert -m 1 <merge-commit>`。遇到冲突时逐文件解决，重新运行相关检查和 `git diff --check`，在 Changelog 记录原因及恢复行为。

不要通过强推改写共享历史，也不要覆盖已发布 tag。已发布版本有问题时发布新补丁版本并说明受影响范围。使用者可从已知可靠 tag 取出完整 Skill 目录，再替换本地安装；替换前保留自己的定制改动。

## 问题分类

可复现缺陷写清触发请求、Skill 与仓库版本、环境、预期与实际结果；来源失效附具体链接；改进建议说明目标使用场景。涉及凭据或隐私时按 [SECURITY.md](../SECURITY.md) 处理，不在公开讨论中附敏感原文。
