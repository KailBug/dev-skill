# 极简科技官网生成

将业务需求变成有清晰信息层级、可信产品呈现和真实交互的响应式网站。参考的是支付宝 AI 付官网的设计语言，而非它的支付业务、品牌资产或页面文案。

## 先确定网站要完成什么

从用户需求或现有项目中确定：品牌、受众、产品价值、主要行动、已有素材与技术栈。信息足够就直接实现；缺少产品或目标时只问影响结果的关键问题，同时继续可独立完成的结构与样式工作。未指定技术栈时选择与交付环境相符的轻量方案，不为视觉效果强制引入框架。

已有项目沿用其路由、组件、字体资源和构建方式，将本风格适配到用户指定范围。用户的品牌指南、页面内容和明确约束优先于此 Skill 的默认值。

## 视觉骨架

实现前阅读 [references/design-system.md](references/design-system.md)，用其中的参数建立项目级设计变量。参考网站的实测值及其来源见 [references/source-observations.md](references/source-observations.md)；只有需要解释来源或精细还原时才读取。

- **白、黑、灰构成主体。** 白色页面，近黑标题，深灰正文，浅灰分割线。默认蓝色只出现在选中、进度、链接和焦点；有品牌色时替换这一小面积点缀。
- **字体和留白先建立层级。** 中文优先系统无衬线。Hero 标题桌面 56px 左右，手机 36px 左右，正文 16px、行高 1.7。不要以大量渐变、插图或标签补救薄弱排版。
- **宽页面、窄首屏文案。** 外框约 1440px，正文约 1160px；居中 Hero 文案 680–760px。横向留白随屏幕缩放，手机 20px。板块使用 72–112px 的纵向节奏，内容紧密处可缩小。
- **圆角有分工。** 普通卡片 18px，场景面板 16px，展示堆叠 22px，内部控件 10–12px，按钮为完整胶囊。不要给所有容器相同的大圆角。
- **主要行动用黑色实心按钮。** 次要行动用白底细边框；按钮高度至少 44px。首屏保留一个主行动，按需要配一到两个次行动。
- **卡片用线条界定，用少量阴影突出重点。** 默认白底、1px 浅灰边框；选中态才添加淡品牌色边线或柔和投影。整体不依赖玻璃效果、全屏渐变或大面积发光。

可按需复制并改造 [assets/design-system.css](assets/design-system.css)。它是有 `.mpw-site` 作用域的起点，不是必须采用的组件框架，也不是原站 CSS。复用资产时保留版权标识，并将本 Skill 的 [MIT 许可文本](LICENSE) 放入生成项目的许可证或第三方声明文件，不覆盖项目原有许可证。

## 根据业务组织页面

先让访客知道“为谁解决什么问题、如何开始”，再给能力和证据。不要机械套用原站的长页面或固定板块数量。

| 业务 | 首屏呈现 | 中部重点 | 主要行动 |
| --- | --- | --- | --- |
| SaaS / 开发工具 | 一句话价值 + 真实界面；命令仅在产品确实需要时出现 | 工作流程、功能、集成、价格 | 试用、开始使用或查看文档 |
| 企业服务 / 咨询 | 面向客户的结果 + 服务概览 | 方法、交付物、真实案例 | 咨询或预约 |
| 品牌 / 工作室 / 个人 | 身份定位 + 代表作品 | 作品、服务、合作过程 | 查看作品或联系 |
| 活动 / 社区 | 主题、日期、参与价值 | 日程、嘉宾、参与说明 | 报名或加入 |

可组合的模块：简洁导航 → 居中 Hero → 产品演示或使用步骤 → 客户/项目证据 → 功能网格或图文分栏 → 案例、价格或 FAQ → 最终行动与页脚。只保留支持当前任务的模块。

不要把终端卡、合作品牌带、数字计数器、聊天机器人和支付文案当作每个网站必备元素。没有真实客户、数据或案例时省略相应证明模块；需要演示内容时明确标注为示例。

## 用少量动作解释状态与关系

默认使用 `cubic-bezier(.22, 1, .36, 1)`。动画参数、卡片轮转、流程与响应式变体见设计参考。

- 按钮和交互卡片：180–240ms 的颜色、边框、投影与 1–3px 位移，悬停和键盘焦点都清晰。
- 正文区块：进入视口时一次淡入并上移到位，约 600–720ms、初始偏移 12–18px，组内错开 50–80ms。首屏标题、正文和 CTA 初始可见。
- 动效确有解释作用时，按需加入产品卡片轮转、步骤推进或轻量界面演示。手机可以改成横向滑动列表或静态纵向流程。
- 自动轮转要有手动切换或暂停控制；悬停、焦点进入及页面不可见时暂停。离开视口后停止无意义的循环。持续移动的品牌带同样提供暂停方式。
- 在 `prefers-reduced-motion: reduce` 下禁用自动轮转、视差、计数滚动和入场位移，直接展示完整内容。交互结果仍正常呈现。

普通过渡用 CSS。仅当复杂时间轴实际需要时，沿用项目已有动画库或选择小型依赖；不用原站的库作为技术要求。可用 [assets/reveal.js](assets/reveal.js) 实现无依赖的渐进增强入场，在组件卸载时调用其清理函数。

## 响应式与可用性

以 1024px、760px 为起点，按内容调整断点：网格从三列到两列到单列；手机导航折叠，CTA 可纵向铺满，流程可改成纵向。不要仅缩小桌面页面。

导航、按钮、复制、筛选、折叠与轮播必须有对应行为。链接使用真实目的地；有待接入的能力明确说明当前状态，不伪造完成提示。菜单支持键盘、Escape、打开状态和焦点回到触发器；FAQ 保留展开语义；只有交互元素才显示可点击反馈。

命令与长链接在局部容器内滚动或换行，不撑破页面。正文保持可读对比度；浅灰辅助文字不承担关键说明。触摸目标至少 44px，焦点可见；不要以悬停作为手机唯一入口。

优先使用用户素材和可授权资源。未提供时用原创界面、简单线性图标或合适的摄影素材，不复制支付宝标识、合作伙伴 logo、专有字体或原站插画。

## 完成后检查

在实际浏览器检查 1440px、1024px、390px 和 320px 的首屏及一个密集板块，核对字体回退、长中文标题换行、按钮、卡片间距和整页横向溢出。通过截图检视后修正，再交付。

实际操作主 CTA、手机菜单及页面采用的交互；验证键盘焦点、减少动画模式和 JS 不可用时核心内容可见。已有项目运行与变更相符的构建检查，不为纯样式变化堆砌测试。

检查字体与图片体积、循环动画暂停和布局稳定性。交付文件或页面、运行/预览方式、验证结果与仍待接入的信息。除非用户要求，不把生成网站扩展为发布、支付接入或采集数据任务。

## 调用示例

> 使用 $minimal-product-website，为一款中文笔记工具生成官网。目标是让学生开始免费试用，品牌色用绿色，不需要终端卡和数字指标。

> 使用 $minimal-product-website，重设计现有摄影工作室首页，保留 React 技术栈和真实作品照片，用黑白、大留白、圆角与克制动效引导预约。

> 使用 $minimal-product-website，生成开发者工具落地页，包含真实安装命令、三步使用流程和可暂停的产品演示，兼顾手机与减少动画设置。
