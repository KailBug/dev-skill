# 设计参数与组件规则

这是从参考网站提炼并面向通用网站调整的设计规范。具体来源与原站参数见 `source-observations.md`。以下除标注为实测的项目外，均是可调整的生成默认值，不代表对原站实现的逐字还原。

## 颜色与字体

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| 背景 | `#ffffff` | 页面与多数卡片 |
| 主文字 | `#0c0c0c` | 标题、主按钮背景 |
| 正文灰 | `#5f5f5f` | 描述、次要正文 |
| 装饰灰 | `#8a8a8a` | 次级图标、非关键装饰；小字号文字另选更深灰 |
| 分割线 | `#e8e8e8` | 1px 边框与分隔 |
| 浅面板 | `#f7f7f7` | 命令区、内嵌示例 |
| 点缀色 | `#1677ff` | 选中、流程进度、少量图标 |
| 点缀浅底 | `#eaf3ff` | 焦点背景、选中状态 |

这些基础色来自原站。更换品牌色时同时定义浅底、边线和满足正文对比度的链接色，不必让按钮全部改成品牌色。

```css
font-family: ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont,
  "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
```

原站正文和标题使用此系统字体栈；浏览器、操作系统和字体回退会改变实际字形。原站数字另有 `Alibaba Sans 102`，通用实现使用系统字体配 `font-variant-numeric: tabular-nums`；无需下载该字体。

| 层级 | 桌面起点 | 手机起点 | 字重 / 行高 |
| --- | --- | --- | --- |
| Hero H1 | `clamp(36px, 4.5vw, 56px)` | 36px | 620 / 1.14（原站实测） |
| 板块 H2 | `clamp(28px, 3vw, 36px)` | 28px | 620 / 1.18–1.3 |
| 大卡片 H3 | 24–28px | 22–24px | 600–620 / 1.3–1.4 |
| 小卡片标题 | 18–20px | 18px | 600 / 1.4 |
| 正文 | 16px | 16px | 400 / 1.7–1.75 |
| 标签、按钮 | 14px | 14px | 500–600 / 1.4 |

不支持连续字重的系统字体会映射到邻近字重；必要时选 600 或 700并视觉核对。中文标题默认正常字距，避免把英文负字距直接套到汉字。英文大标题可用约 `-.02em`。正文左对齐，首屏及板块简介可居中。

长中文标题优先用宽度和 `text-wrap: balance` 控制换行。不要为桌面效果随意写固定 `br`，以免手机末行只剩一两个字；确需人为断句时为窄屏另作处理，并检查320px和390px的实际效果。

## 容器、留白、圆角与阴影

- 页面外框 `max-width:1440px`，内容 `max-width:1160px`，均居中。横 padding `clamp(20px,4vw,48px)`；嵌套容器只施加一次外侧 padding，避免把有效内容区缩得过窄。
- Hero 主文案上限 760px，说明约 680px；导航约 60px 高；Hero 顶部留白约 80–104px，手机约 40–52px。这些留白根据标题行数调整。
- 布局间距使用 `4,8,12,16,20,24,32,40,48,64,80,96,112`，这是归纳出的通用尺度，而非原站统一 token。
- 内容板块纵 padding 72–112px，手机 48–64px。卡片 padding 24–32px，紧凑移动卡片 20–24px；网格 gap 16–24px。
- 圆角：卡片 18px、场景面板 16px、展示堆叠 22px、内部控件 12px、胶囊按钮 999px。原站 Hero 按钮实测 99px；在44px高度下均为胶囊外观。
- 平面卡片默认不投影或仅 `0 1px 2px rgb(0 0 0 / .04)`。浮起展示可用 `0 16px 40px rgb(0 0 0 / .06)`。重点产品允许淡点缀色阴影，整个页面只在少数聚焦模块使用。

## 组件

### 导航与 Hero

导航白底细下边线，品牌靠左，少量栏目居中或顺排，账号/转化按钮靠右。有固定导航时为锚点预留 `scroll-margin-top`；不要遮挡内容。手机使用折叠菜单，明确打开/关闭反馈。

Hero 的视觉顺序为标题 → 简短说明 → 行动 → 产品展示。标题传达具体价值，说明控制在两三行；靠排版与留白建立视觉中心。有真正代表产品的界面或作品图时可以使用图文双栏，保留同样的层级与轻量表面。

主按钮黑底白字，次按钮白底细边；高度44px起，横 padding20px。悬停上移2px并增加轻投影，按下回到原位。边框、颜色和 transform 分别声明 transition，不使用 `transition:all`。

### 演示、命令和流程

产品演示使用有细边线的白色容器或浅灰内部面板。内容要解释真实产品，不用随机代码装饰业务网站。

开发者产品的命令卡可包含小型窗口头、单行代码和复制按钮。代码用等宽字体；手机代码列 `min-width:0`，内部 `overflow:auto`，复制按钮 `flex-shrink:0`。复制失败时显示可手动选择的内容，而不是假装成功。

步骤由圆形线性图标、细连线和短标签组成。当前步骤用点缀色边框/浅底，已完成步骤用明确状态；桌面横排、手机纵排。装饰性推进不能被理解为用户后台任务真的完成，真实任务应由业务状态驱动。

### 卡片与产品轮转

普通功能网格保持标题、说明、示例的稳定顺序。图标简洁，不为每张卡片增加多彩大底块。长文案不强制相同高度，CTA 可通过布局对齐。

轮转产品是可选的视觉重点：中央卡清楚完整，相邻卡逐步缩小和后退，突出“同一体系的不同能力”。原站使用3D透视；通用实现可用更简单的 translate/scale 达到层级，不必引入 GSAP。

推荐中心比例1、相邻 .92、外围 .84，纵向位移0/18/36px；转场600–800ms，静止2–4s后再切换。参数是生成建议。正文不可长期小到不能读；所有产品均应有可访问的链接/静态列表。提供上一项、下一项与暂停；焦点处于卡片时不要重排它。

手机优先改成原生横滑 + `scroll-snap-type:x proximity` 或单列，保留手动入口，不把五张3D卡挤进390px宽度。

### 证据、图文和 FAQ

合作品牌带只展示真实授权关系；重复循环副本 `aria-hidden="true"` 且不可聚焦。减少动画模式变为静态列表。边缘淡出可用 mask，但不能遮住唯一证据或操作。

数值从可靠内容取得，最终值应存在于HTML文本中。计数只为非关键数字提供一次渐进展示；无需在每次滚动重播或从0开始长时间闪动。

图文分栏采用白底/浅面板与内容差异，不让每个板块都变成相同卡片阵列。FAQ 可使用原生 `details/summary`，或语义正确的按钮加受控内容；页脚的深浅取决于品牌和内容。

## 动效时序

| 动作 | 通用默认 | 降级 |
| --- | --- | --- |
| 按钮、卡片反馈 | 180–240ms；`cubic-bezier(.22,1,.36,1)` | 保留清晰的即时状态变化 |
| 视口入场 | 600–720ms；opacity + translateY 12–18px | 所有内容直接可见 |
| 同组错开 | 50–80ms；通常不超过5–6个项目 | 无错开 |
| 步骤展示 | 分步推进；总周期约8–12s | 静态或用户操作推进 |
| 产品轮转 | 600–800ms转场；2–4s停留 | 静态网格/手动切换 |
| 数字展示 | 800–1100ms，一次 | 直接最终值 |

默认不使用 blur 入场。它虽然出现在原站，但大面积滤镜会增加渲染成本。只动画 transform/opacity 为主，避免持续改变 width/height/left/top，进度用 scaleX/scaleY。

JS 加载成功且观察器可用后再为屏外元素设置入场初态；JS失败、观察器缺失或用户减少动画时内容保持可见。组件卸载断开观察器/定时器；路由切换不累积监听；后台或屏外停止循环。

## 响应式起点

| 范围 | 布局选择 |
| --- | --- |
| 大于1024px | 三列功能网格；可用双栏图文、横向步骤和聚焦轮转 |
| 761–1024px | 两列卡片，长图文必要时上下排列；标题保持明确 |
| 760px及以下 | 单列网格，导航折叠，CTA可纵排，20px边距，流程纵排 |
| 320–390px | 针对长标题/代码/链接检查，不缩小正文来强行塞入 |

这些是内容驱动的默认断点，不是原站所有媒体查询的列表。表格可改成卡片或在带可见提示的局部区域滚动；不得通过整页 `overflow-x:hidden` 掩盖溢出。图片保留宽高或 aspect-ratio，避免加载时布局跳动。

## 资产使用接口

`assets/design-system.css` 包含基础变量与 `.mpw-*` 示例类。最外层用 `.mpw-site`，内部可组合 `.mpw-shell`、`.mpw-container`、`.mpw-hero`、`.mpw-actions`、`.mpw-button`、`.mpw-card`、`.mpw-grid`、`.mpw-section`。独立页面可将 `.mpw-site` 加到body，资产会移除其默认margin；嵌入现有页面则沿用项目的外侧间距。已有项目将变量映射到自己的token系统即可。

`assets/reveal.js` 导出 `initReveals({root})`，对 `.mpw-reveal` 做一次入场并返回清理函数。页面模块调用示例：

```js
import { initReveals } from './reveal.js';
const dispose = initReveals();
// SPA/组件卸载时调用 dispose()；服务端渲染阶段不要调用。
```

静态页面使用 ES module 时，通过本地HTTP服务或项目开发服务器预览；直接双击 `file://` 页面可能使模块导入被浏览器拦截。

这两个资源不包含完整网站、复制功能或轮播控制器；这些行为根据业务实现并实际验证。
